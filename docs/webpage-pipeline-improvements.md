# Webpage generation improvements

## What changed

The generator previously illustrated every website with a preset SVG and reused the same section skeleton. The renderer now composes a page around its content and optional design intent. No Ledify application frontend was added: this work concerns the websites generated by the backend and their existing preview.

| Files | Purpose |
| --- | --- |
| `Service/ai/webpageGeneration.mjs`, `templates/webpage/webpageSchema.mjs` | Precise planning/content instructions; optional industry/audience/conversion/imagery/density/hero design brief; optional section compositions; product catalog, statistics and comparison sections. Still two AI requests, with existing bounded retries. |
| `Service/webpageContentValidator.mjs` | Validates new fields, preserves source-grounding checks, requires supplied statistic values and limits design intent. Existing plans without new fields remain valid. |
| `Service/webpageDesignService.mjs`, `Service/webpageLayoutService.mjs` | Chooses purposeful editorial, showcase, bento, timeline, list or grid arrangements. Legacy content gets deterministic defaults. Catalog CTAs reach products. |
| `Service/webpageThemeService.mjs` | Industry palettes, healthcare/retail directions, font pairings and density tokens. Existing primary/accent overrides remain supported. |
| `Service/webpageAssetService.mjs` | Optional licensed local image catalog, safe real paths, size/dimension limits, PNG integrity checks, JPEG signatures, bounded asset count, attribution and image-free fallback. Exact brand/product matching prevents unrelated photos being assigned to a product. No native image decoding or network retrieval in production. |
| `renderer/webpage/components.mjs`, `styles.mjs`, `webpageRenderer.mjs` | Content-led or image-led heroes, asymmetric capabilities, project/product showcases, editorial prose, menu lists, timelines, semantic statistics, FAQs and truthful contact actions. Controlled fluid headings, readable body copy, mobile stacking, touch controls and keyboard focus. Removed unused `illustrations.mjs` and placeholder project artwork. |
| `Service/webpageStaticValidator.mjs` | Bounded dynamic image allowlist; local asset references, image dimensions/alt text, HTML structure, heading hierarchy, navigation, trusted JS, safe SVG/CSS. Reports compositions and warnings; marks visual quality as requiring review. |
| `Service/generateService.mjs`, `webpageArtifactService.mjs` | Resolves images before rendering, includes image diagnostics, preserves ZIP/API contracts and supports a configured persistent webpage root. |
| `renderer/webpage/previewViewer.mjs` | Desktop 1280px, Tablet 768px and Mobile 390px are actual iframe widths. Narrow hosts scroll the preview instead of silently shrinking the chosen viewport. |
| `tests/webpage`, `tests/regression/webpage*.test.mjs`, package files | Seven deterministic industry samples, catalog/security regression tests and development-only Playwright. Browser checks cover four widths, offline ZIPs, keyboard behavior, images, console errors and sandbox isolation. |

## Reproduce locally

```sh
npm ci
npm test
npm run test:webpage:samples
# Windows uses installed Edge by default. On Linux/macOS:
npx playwright install chromium
npm run test:webpage:browser
```

`PLAYWRIGHT_CHANNEL` can override the Windows browser channel. Playwright is a devDependency and is omitted by the production Docker build. No browser processes run as part of normal generation. Sample generation uses fixture AI responses by default; it does not call Gemini, MongoDB or external source websites. Do not add `live` unless deliberately testing the paid/provider path.

Screenshots and browser diagnostics are under `generated/webpage-samples/<industry>/screenshots/` and `generated/webpage-samples/browser-verification.json`. These generated outputs are ignored by Git. The seven cases are pharmaceutical, restaurant, startup, portfolio, education, store and professional business. Screenshots at 375, 768, 1024 and 1440 pixels support manual review; geometry checks alone cannot establish aesthetic quality. An artificial test image separately verifies the real local-image path and is not presented as pharmaceutical photography.

## Optional licensed imagery

Set `LEDIFY_WEBPAGE_IMAGE_MANIFEST` to an absolute JSON catalog path available inside the deployed service. Images must live within that catalog's directory (including real symlink targets). Example:

```json
[
  {
    "industry": "healthcare",
    "role": "hero",
    "file": "images/licensed-laboratory.jpg",
    "alt": "Describe what the licensed laboratory photograph actually shows",
    "creator": "Actual photographer or rights holder",
    "license": "Actual license and required attribution",
    "caption": "An optional truthful caption"
  }
]
```

Use your own licensed image and its real attribution; the example does not supply an image or usage rights. Supported industries: healthcare, hospitality, technology, creative, education, retail, professional and general. Roles: `hero`, `section` (requires matching `sectionType`) or `item` (requires exact `brandName`, `sectionType`, `itemTitle`). An optional `brandName` also scopes hero/section images to a specific brand. Item images should depict that actual supplied item. The catalog is deployment configuration, never a user-upload or AI-supplied path.

At most four unique images are bundled, each at most 2 MiB and 100–2400px per side. Use optimized JPEG or eight-bit non-interlaced PNG. The catalog itself is at most 64 KiB/100 entries. PNG chunks/checksums and decompressed raster length are checked with a bounded decoder; JPEG validation checks framing/dimensions, with browser tests verifying actual display. Full JPEG decoding is deliberately left to the browser. Unavailable/corrupt catalogs produce a diagnostic and a complete content-led website. Essential images, CSS and JS are local in the ZIP; no remote fonts or arbitrary stock URLs are introduced. License metadata records the operator's assertion; Ledify cannot independently establish ownership.

## Deployment and limitations

- Production needs no new system packages for this webpage work. The existing presentation rendering packages are unaffected.
- Optionally set `LEDIFY_WEBPAGE_ROOT` to a writable persistent Render disk directory. Generation and delivery use the same root. Without persistent storage, artifacts can disappear on redeploy; this is not solved by changing a URL.
- Preserve `WEBPAGE_APP_ORIGIN` as the exact frontend origin when embedding the existing preview cross-origin. Sandbox restrictions remain intact.
- Existing generation and preview/download routes and response versions remain unchanged. New metadata is additive. Older stored content without design briefs/compositions still renders.
- Sites remain single-page static websites. No checkout, order confirmation, authentication, forms or reservation processing is fabricated. Contact actions only use supplied details.
- No real licensed catalog is configured by this change. Industry samples deliberately demonstrate the content-led fallback. Real image-rich results require appropriate assets.
- No live Gemini quality test or Render deployment is included in the deterministic checks. Provider creativity, factual claims beyond explicit numerical/contact/testimonial checks, and real-world accessibility still need review.

## Verification

- Full regression suite: **247 passed, zero failed** (includes presentation/document regressions).
- Final focused webpage suite after layout refinements: **38 passed, zero failed**.
- Deterministic generation: seven complete sites and ZIPs, with zero live AI calls.
- Browser verification: seven industries × four widths (28 responsive cases), plus no-JS navigation, desktop/tablet/mobile preview widths, opaque-origin isolation and a separate licensed-catalog image loading check in the sandbox and offline.
- Screenshots reviewed: all seven desktop hero compositions, restaurant mobile, and additional education/restaurant refinements. These are qualitative reviews, not an objective beauty score or exhaustive accessibility certification.
- Changes are local until committed/pushed and deployed. Existing production artifacts are not rewritten.
